# PI Runtime 按需下载与设置权限设计

## 目标

将 PI、PI-Web 与 Node 运行时从 Banana Box 主安装包中移出，改为用户首次需要时按需下载、校验、安装和启动；同时将 PI-Web 配置修复迁移到独立二级窗口，并限制云端协作配置页仅对云端管理员可见。

成功标准：

- Windows 主安装包不再包含 `pi-web-runtime.zip`，目标体积为 6–10 MiB。
- 用户首次点击 PI-Web 时，能在不打开终端、不安装 Node.js 的情况下完成下载并启动。
- 下载、校验、解压、更新和启动均有清晰进度与可恢复失败状态。
- PI 与 PI-Web 可独立于 Banana Box 更新；更新失败时旧版本仍可启动。
- PI-Web 日常页面保持简洁，配置修复在单独窗口中完成。
- 未登录用户与没有云端管理员权限的用户无法看到或调用云端协作配置管理功能。

## 非目标

- 不直接让正式用户运行 `npm install`、`npx` 或其他终端命令。
- 不将 PI-Web 嵌入 Banana Box 的 720×520 主窗口。
- 不在本次工作中重写 PI-Web 本身的 UI 或功能。
- 不改变普通用户登录、加入工作区、同步和协作功能的可用性。

## 运行时发布源

新建独立公开仓库 `felix1709/banana-box-pi-runtime`，专门发布 Windows x64 运行时。不得将独立运行时发布为 `felix1709/banana-box` 的最新 Release，避免覆盖 Banana Box 现有应用更新器使用的 `latest.json`。

每个运行时版本发布以下文件：

- `pi-runtime-win-x64-<runtimeVersion>.zip`：Node、PI、PI-Web 与其运行依赖。
- `pi-runtime-win-x64-<runtimeVersion>.zip.sig`：运行时压缩包签名。
- `pi-runtime.json`：稳定清单，记录 runtime、PI 与 PI-Web 版本，文件大小、SHA-256、下载地址、签名地址和发布时间。
- `pi-runtime.json.sig`：清单签名。

Banana Box 内嵌公钥，下载前验证清单签名；下载后验证文件 SHA-256 和压缩包签名。运行时构建机使用固定的 PI / PI-Web 版本生成包并完成启动冒烟测试，用户设备只下载已验证产物。

## 本地检测与启动顺序

用户点击 PI-Web 后，后台按以下顺序检查：

1. 检查 `app_data/pi-runtime/current` 是否指向完整、校验通过且健康检查成功的 Banana Box 托管运行时。
2. 检查 `127.0.0.1:30141` 是否已有可访问的 PI-Web；若是则允许直接打开。
3. 检测用户自行安装的兼容 Node / PI-Web 命令；只在能验证版本和启动参数时提供“使用本机环境”选项，不把未知环境作为默认路径。
4. 都不可用时显示下载入口，不自动开始下载。

托管运行时使用 `app_data/pi-runtime/versions/<runtimeVersion>` 保存；`current` 记录已激活的版本。旧版本在新版本通过启动健康检查后保留一个版本，供失败回退使用。

## 下载、安装与更新体验

PI-Web 主页面显示以下状态：

| 状态 | 主操作 | 辅助信息 |
| --- | --- | --- |
| 未安装 | 下载并启动 PI-Web | 包大小、版本、下载源 |
| 下载中 | 取消下载 | 百分比、已下载/总大小、速度、剩余时间 |
| 校验中 | 禁用重复操作 | 正在验证文件安全性 |
| 准备中 | 取消（仅在安全时） | 正在解压和检查运行环境 |
| 已安装 | 启动 PI-Web | 当前版本、检查更新、卸载 |
| 有更新 | 更新后启动 / 继续使用当前版本 | 新旧版本、包大小、更新说明 |
| 失败 | 重试 | 不泄露敏感信息的具体失败原因 |

后台任务不弹出命令行窗口。Rust 后端负责下载、进度事件、签名校验、临时目录解压、原子切换版本与启动健康检查；启动 PI-Web 时使用托管运行时里的 Node 子进程。前端只订阅结构化进度事件并渲染。

更新采用“下载到临时目录 → 校验 → 解压至新版本目录 → 启动健康检查 → 原子切换 `current`”流程。下载中断、校验失败、解压失败或新版本启动失败时，删除临时内容并保留当前可用版本。

## PI-Web 配置修复二级窗口

PI-Web 主页面只呈现运行状态和主操作。检测到配置不兼容时，主页面显示简短状态与“打开配置修复”按钮。

点击后创建独立的 Tauri 二级窗口 `pi-web-repair`：

- 显示 Provider、模型、设置文件与兼容项的检测结果。
- 提供“一键修复配置”按钮。
- 修复过程中显示步骤状态；完成后可关闭窗口并回到主页面启动 PI-Web。
- 自动修复失败时才显示简明的手动处理说明。
- 窗口内内容可滚动，窗口大小固定且不影响主面板布局。

二级窗口调用现有的 PI-Web 配置检测与修复命令；敏感 API Key 不在窗口中显示、写入日志或通过前端传递。

## 云端协作配置权限

云端协作配置区块的可见条件固定为：

```ts
auth.user !== null && auth.isCloudAdmin === true
```

因此以下用户都不显示云端协作配置区块、Supabase 地址、Anon Key、建表 SQL 与保存按钮：

- 未登录用户；
- 新注册但未取得云端管理员权限的用户；
- 已登录的普通协作者。

后端的保存云端配置和导出初始化 SQL 命令也必须执行管理员授权校验，不能只依赖前端隐藏。没有权限时返回稳定错误码 `CLOUD_ADMIN_REQUIRED`，前端不展示管理入口。

## 发布流程改造

Banana Box 常规发布不再执行 `prepare:pi-web`，也不在 `tauri.conf.json` 的 `bundle.resources` 中包含 `pi-web-runtime.zip`。

运行时发布流程独立执行：固定 PI 与 PI-Web 版本、安装生产依赖、清理调试映射和文档、压缩运行时、生成清单与签名、启动 PI-Web 冒烟测试、发布到独立运行时仓库。

Banana Box 发布验证增加两项：

- 确认主安装包不包含 `pi-web-runtime.zip`。
- 在干净用户数据目录中模拟“首次下载 → 校验 → 启动”和“有旧版本时更新失败回退”。

## 测试策略

- Rust 单元测试：清单解析、版本比较、签名/哈希失败、临时目录清理、原子切换和回退。
- Rust 集成测试：本地测试服务器模拟下载、断点/取消、损坏压缩包和健康检查失败。
- Vue 组件测试：未安装、下载进度、取消、失败重试、可用更新、使用旧版本与修复窗口入口。
- 权限测试：未登录、普通用户、管理员三种状态下云端配置区块和命令授权均符合规则。
- 手工验证：在无 Node、无 PI、干净 AppData 的 Windows 环境中完成首次下载与启动；再验证离线启动、更新、失败回退和二级修复窗口。
