# Project Archive Sync Design

## Goal

项目管理模块要让“归档”成为一个稳定的数据状态，而不是只在当前页面临时隐藏项目。用户归档项目后，再点击同步，项目不能因为云端旧数据又回到进行中列表。

## User workflow

1. 用户在“项目管理”里默认看到进行中项目。
2. 用户点击项目卡片上的“归档”，项目从进行中列表消失。
3. 用户点击“归档项目”，可以查看已归档项目。
4. 用户可以在归档区恢复项目，恢复后回到进行中列表。
5. 用户只能在归档区永久删除项目，删除前必须二次确认。
6. 用户点击同步时，同步应尊重最近一次项目状态变更。

## Data rule

项目的 `archived` 是正式状态。同步合并时不能无条件用云端项目覆盖本地项目：

- 如果本地项目 `updatedAt` 晚于云端 `updated_at`，保留本地项目。
- 如果云端项目 `updated_at` 晚于本地 `updatedAt`，采用云端项目。
- 如果本地和云端时间无法判断，保持现有行为，避免引入复杂冲突系统。

这条规则先解决用户遇到的核心问题：本地刚归档，云端还是旧的未归档状态，同步后不能把项目“复活”。

## Cloud write-through

当用户在项目页执行归档或恢复，并且当前已经登录云端工作区时，前端应把更新后的项目状态上传到云端。这样另一个设备或下次同步也能看到归档/恢复结果。

如果当前没有登录或没有云端工作区，归档仍然保留在本地；后续同步时由“本地更新时间优先”规则保护它不被旧云端数据覆盖。

## Tests

需要补充自动化测试：

- 本地项目已归档且更新时间更新时，拉取云端旧的未归档项目后，本地仍保持归档。
- 云端项目更新时间更新时，拉取云端恢复状态后，本地采用云端状态。
- 项目页归档/恢复后，在已登录云端工作区时会上传更新后的项目状态。

## Non-goals

本次不重写完整 `sync_outbox`、`revision`、`deleted_at` 同步引擎；这些字段已经在数据库中预留，但完整双向同步属于更大工程。当前只修复用户可见的项目归档同步闭环。
