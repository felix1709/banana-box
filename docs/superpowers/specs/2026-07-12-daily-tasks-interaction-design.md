# 当日任务紧凑交互设计

- 日期：2026-07-12
- 状态：设计已确认，等待全部关联规格复核
- 范围：当日任务的新建区、任务卡片、进度滑块与“复制日报”反馈。

## 目标

让用户能在紧凑的单任务卡片中快速填写编号、任务名称和完成度；进度通过拖动直观控制，日报复制反馈短暂且明确，页面不再被重复按钮和分割线打断。

## 布局

1. 每条任务是一个独立卡片；编号、名称、进度条和百分比在同一行。
2. 同一编号下的任务保留分组标题，但分组容器不使用嵌套卡片外框，避免“卡片套卡片”。
3. 进度控件使用方案 1：4px 浅色轨道、主色填充、圆形滑块。数值紧邻轨道显示。
4. 进度控件旁显示浅灰提示“拖动调整完成进度百分比”。
5. 备注在卡片底部，占用完整一行的小字号输入区域。
6. 新建区复用编号、名称、进度条和百分比的横向结构；添加按钮为图标按钮。

## 交互

1. 进度条范围固定为 0 到 100；拖动时立即更新当前显示的百分比，但只有点击保存才写入本地数据库。
2. 保存和删除是卡片右上角的图标按钮。默认低透明度，卡片悬停或按钮聚焦时显示完整；仍具有可访问名称与 tooltip。
3. 已结算日期下，输入框、滑块、保存和删除都禁用。
4. 页面右上角的“复制日报”成功后显示对勾 1.2 秒，随后自动恢复复制图标。
5. “复制日报”失败时保持复制图标，并调用现有轻量 Toast；不显示持续的成功状态。
6. 不新增任务编号旁的复制按钮。

## 数据与兼容

- 日报格式、任务编号分组、备注、进度百分比和现有 SQLite 数据结构保持不变。
- 任务的投入时间字段不在界面显示，创建时仍以 0 写入以兼容现有接口。
- 不引入自动保存，避免滑块拖动产生连续数据库写入。

## 验收

1. 新建任务可通过编号、名称、滑块、备注创建，且不显示数字进度输入框。
2. 已有任务使用 range 控件，百分比文本随 input 事件同步。
3. 点击保存仍发送正确的标题、进度、备注和兼容字段。
4. 复制日报成功时对勾在 1.2 秒后恢复；失败时图标不变且显示 Toast。
5. 保存、删除图标不占据正文行空间，键盘聚焦仍可见。
6. 既有日报复制、结算只读与日期切换测试继续通过。
